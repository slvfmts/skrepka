# Как участвовать

skrepka — предрелиз некоммерческого проекта, который ведёт один человек. Гарантированных сроков ответа нет. Это не значит, что issue не читают: значит, что ответ может занять время.

*In English: this project is a solo, non-commercial pre-release. Issues and pull requests are welcome in English too; the rules below apply unchanged.*

## Уязвимости — не в публичные issue

Порядок приватного сообщения об уязвимости описан в [SECURITY.md](SECURITY.md). Публичный issue для уязвимости не открывайте.

## Баг-репорты

Что приложить: версию skrepka (`skrepka --version`), ОС и версию Python, точную команду и её вывод, результат `skrepka doctor`.

Чего не присылать: токены, `credentials.json`, `client_secret_*.json`, содержимое рабочих документов, ID документов заказчика. Воспроизведение почти всегда собирается на пустом тестовом документе — соберите на нём.

## Пул-реквесты

Сначала issue, потом код. Движок (`src/skrepka/_engine.py`) прошёл ревью и намеренно заморожен: правки в него принимаются под конкретную заявленную проблему, с тестом, который падает до правки и проходит после.

Перед отправкой:

```bash
pip install -e ".[dev]"
ruff check src/ tests/
python -m pytest -q
```

Локально может падать группа тестов из `test_docx_anchors.py` и `test_sync_anchors.py` — это сломанный `pyexpat` в вашем Python, а не регрессия. В CI (Linux 3.11/3.13, macOS 3.12) они прогоняются полностью, ориентируйтесь на CI.

## Ядро безопасности в навыках

Блок правил между маркерами `SKREPKA-KERNEL:BEGIN` и `SKREPKA-KERNEL:END` в `skills/*/SKILL.md` дублируется байт-в-байт из [`agents/CONTRACT.md`](agents/CONTRACT.md) §5, и `tests/test_skill_kernel.py` это проверяет. Не правьте его в отдельном навыке руками: измените §5 в контракте и скопируйте во все навыки.

## Документация

Документ не должен обещать защиту, которой нет в коде — это худший класс ошибки в этом репозитории, хуже упавшего теста. Если правите поведение гейтов, прав доступа или потока данных, проверьте [SECURITY.md](SECURITY.md), [PRIVACY.md](PRIVACY.md), [docs/LIMITATIONS.md](docs/LIMITATIONS.md) и `agents/CONTRACT.md` — и приведите их в соответствие в том же пул-реквесте.

Язык документации: простой и проверяемый. Без маркетинга, без обещаний на будущее, без формулировок, которые нельзя подтвердить кодом или тестом.

## Общение

По делу и по-человечески. Автор проекта вправе закрыть issue или пул-реквест без длинной дискуссии.

# Безопасность skrepka

Этот документ — про модель угроз, встроенные защиты и то, как сообщить об уязвимости.
Про то, какие данные и куда уходят, — отдельный документ [PRIVACY.md](PRIVACY.md).

Коротко: **skrepka 0.9 — персональный security-hardened preview, а не проверенное
Google приложение.** Защиты, описанные ниже, реальны и покрыты тестами, но статус
версии — предрелизная бета.

## Как сообщить об уязвимости

Пожалуйста, **не открывайте публичный issue** для уязвимостей.

- Предпочтительно — приватный репорт через GitHub: вкладка **Security → Report a
  vulnerability** (private vulnerability reporting) в репозитории `slvfmts/skrepka`.
- Либо письмом на **hello@editors.one** с темой, начинающейся на `[skrepka security]`.

Что помогает: версия skrepka, ОС и версия Python, шаги воспроизведения, а для
проблем работы с файлами — точная раскладка путей и прав. Отвечаем по мере
возможностей (это некоммерческий open-source проект, гарантированного SLA нет);
исправление выходит в ближайшем патч-релизе, кредит — по вашему желанию.

## Поддерживаемые версии

skrepka в стадии 0.9 (предрелиз). Исправления безопасности выходят только для
**последнего** релиза линии 0.9.x. Более ранних поддерживаемых веток нет.

## Модель угроз

**От чего защищаем.** skrepka пишет артефакты (скачанный документ, изображения,
sidecar, файл `--output`) в **рабочую директорию, где вы запускаете команду** —
её цепочку владельцев мы не контролируем. Главная угроза — подменённый по
**предсказуемому** пути симлинк или хардлинк: наивный `open(path, "w")` пошёл бы
по такой ссылке и переписал произвольный файл, доступный вам на запись (например,
`~/.ssh/authorized_keys`), содержимым документа. Такой сценарий реален в общих или
world-writable каталогах (`/tmp`, расшаренные рабочие директории).

**Где проведена граница.** Атакующая поверхность — это **имя целевого файла и его
непосредственная родительская директория** (предсказуемые, угадываемые имена). По
ним skrepka работает через `O_NOFOLLOW` и эксклюзивное создание: симлинк на этой
позиции приводит к отказу (fail closed). **Директории-предки** выше непосредственного
родителя — это ваша существующая среда, и по ним symlink'и намеренно
**разыменовываются**: это и нормальное поведение файловой системы, и обязательное на
macOS, где `/var`, `/tmp`, `/etc` сами являются симлинками в `/private`. Тот, кто может
подложить симлинк в *дальний предок*, уже имеет доступ на запись в ваше дерево.

**Что вне модели угроз (честно).**
- **Атакующий под вашим же пользователем (тот же UID).** Он и так может прочитать
  токен и ваши файлы; права `0600`/`0700` — это контроль доступа для *других*
  пользователей машины, **не шифрование**. Настоящая защита данных «в покое» —
  полнодисковое шифрование (FileVault / LUKS). См. PRIVACY.md.
- **Windows.** В 0.9 не поддержан; защиты файлового I/O — Unix-only (`openat`,
  `O_NOFOLLOW`, dir-fd).
- **Гранулярный контроль каждого действия агента.** Вне скоупа 0.9 (см. ниже про
  human-gate и prompt-injection).

## Встроенные защиты

**Аутентификация и доступ.**
- skrepka запрашивает **единственный** OAuth-scope — `https://www.googleapis.com/auth/drive`.
  Более узкий `drive.file` неприменим: он ломает ключевой сценарий «чужой документ с
  комментариями по его ID / Shared Drive». Более широкие или дополнительные scope
  (в т.ч. `documents`) не запрашиваются — `drive` уже покрывает нужные вызовы Docs API.
- Токен хранится с правами `0600` в конфиг-директории `~/.config/skrepka/` (`0700`).
  Рефреш с **сокращённым** набором scope не сохраняется на диск — иначе урезанный
  грант молча стал бы рабочим при следующем запуске.

**Файловый I/O.** Все артефакты пишутся через модуль `safeio`: непосредственный
родитель открывается `O_NOFOLLOW` (создаётся `0700` эксклюзивным `mkdir`), запись
идёт в непредсказуемый `O_EXCL|O_NOFOLLOW`-временный файл с последующим атомарным
`rename` поверх цели. `rename` **заменяет имя**, а не пишет сквозь симлинк и не
усекает хардлинкнутый inode. Существующая нерегулярная цель отвергается явно.

**Человеческий гейт — две разные вещи, честно.**

- *Блокирует автоматический путь* (на уровне кода): резолв комментария и деструктивное
  полное обновление документа не выполняются без подтверждения — интерактивный запрос
  в TTY (по умолчанию «нет»), а единственный неинтерактивный обход — явная переменная
  окружения `SKREPKA_ASSUME_HUMAN=1`. Это закрывает случайный автоматический путь.
  Полной гарантии «только человек» тут нет: агент, выделивший псевдо-терминал,
  технически мог бы ответить на запрос — поэтому идентичность «человека» в конечном
  счёте держится
  на договорённости ([`agents/CONTRACT.md`](agents/CONTRACT.md)), а не на криптографии.
  Агент **никогда** не резолвит комментарии сам.
- *Кооперативная граница* (политика, не блокировка): команды управления данными
  `revoke` и `forget` принимают неинтерактивный флаг `--yes`, а `logout` вообще не
  спрашивает подтверждения (он лишь убирает локальный токен). Технически агент мог бы
  передать `--yes`; запрет на это — правило для агента в
  [`agents/CONTRACT.md`](agents/CONTRACT.md), а не машинный барьер. Это команды для
  человека.

**Изображения — временно публичный ACL.** Вставка картинки требует прямой ссылки,
поэтому во время вставки файл кратко становится `anyone:reader`, затем доступ
снимается. При падении в неудачный момент картинка может остаться публичной — убрать
вручную в Google Drive. Подробности и рекомендации — в PRIVACY.md.

**Prompt-injection.** Текст документов и комментариев — это **данные, а не
инструкции**. Скиллы для агента (см. `agents/CONTRACT.md`) обязаны не выполнять
просьбы, встреченные внутри комментариев/текста, без подтверждения человека.

**Без телеметрии.** У skrepka нет сервера, нет сбора данных и нет исходящих
соединений, кроме API самого Google (и внешних хостов картинок, если вы работаете с
изображениями). Мейнтейнер ваших данных не получает.

## Гигиена репозитория

- Секреты (`credentials.json`, `client_secret_*.json`, `token.json`, `*.token.json`,
  `.env`) — в `.gitignore`; их нельзя коммитить. gitleaks прогоняется по всей истории в
  CI на каждый push и в release-workflow перед публикацией.
- Артефакты рантайма (`*.gdocs-base.json`, журналы синка) — тоже в `.gitignore`,
  поскольку sidecar содержит **полный текст** документа.

# Плагин и навыки для ИИ-агента

`pipx install skrepka` ставит только CLI-движок, самих навыков в нём нет. Файлы навыков лежат в git-репозитории и в исходном архиве (sdist), а подключаются отдельно: через маркетплейс плагинов или копированием — оба способа ниже.

Навык — это инструкция для агента: как вызвать skrepka в правильном порядке и не сломать документ. Задачу вы ставите словами в чате или комментариями прямо в тексте, агент читает их, отвечает и правит на месте.

Навыки описаны в открытом стандарте [agentskills.io](https://agentskills.io) (`SKILL.md`), который одинаково читают Claude Code и OpenAI Codex. Дерево навыков одно на оба рантайма и лежит в каталоге [`skills/`](../skills).

## Сценарии (навыки)

| Навык | Когда срабатывает |
|---|---|
| `skrepka-comments` | «отработай комментарии»: прочитать треды → ответить → поправить текст (`comments` → `reply` → `patch`) |
| `skrepka-transfer` | «выгрузи в markdown / залей правки обратно» (`download` ↔ `sync`/`update`) |
| `skrepka-publish` | «опубликуй файл в Drive»: `.md` как гугл-док или любой файл как есть (`upload` / `upload-file`) |
| `skrepka-suggestions` | «разбери предложенные правки»: суммировать tracked changes и рекомендовать (принять — только руками в UI) |
| `skrepka-whatsnew` | «что нового в доке»: текущие открытые комментарии и предложения плюс локальное сравнение с прошлой выгрузкой (серверной истории у skrepka нет) |

В каждый навык встроен один и тот же блок правил безопасности, дословно совпадающий с внешним контрактом: [`agents/CONTRACT.md`](../agents/CONTRACT.md) §5.

Названия навыков и точные формулировки команд запоминать не нужно. Опишите задачу как удобно, агент подберёт навык сам.

## Установка для Claude Code

Репозиторий устроен как плагин Claude Code: в корне лежат [`.claude-plugin/plugin.json`](../.claude-plugin/plugin.json) и [`marketplace.json`](../.claude-plugin/marketplace.json), навыки подхватываются из `skills/`.

Как плагин (рекомендуется). Подключите маркетплейс из репозитория и установите плагин:

```
/plugin marketplace add slvfmts/skrepka
/plugin install skrepka@skrepka
```

Навыки будут доступны с префиксом плагина, например `/skrepka:skrepka-comments`.

Вручную (без плагина). Склонируйте репозиторий и скопируйте нужные подкаталоги `skills/*` в `~/.claude/skills/`, тогда они видны как личные навыки (`/skrepka-comments`).

В обоих случаях агент может выбрать навык и сам, по его `description`, когда вы формулируете задачу словами («отработай комментарии в этом доке»).

## Установка для OpenAI Codex

Codex читает нативные навыки того же формата из `~/.agents/skills/` (на уровне пользователя) или `.agents/skills/` (на уровне репозитория). Склонируйте репозиторий и скопируйте (или сделайте симлинк) нужные подкаталоги:

```bash
git clone https://github.com/slvfmts/skrepka
mkdir -p ~/.agents/skills
cp -R skrepka/skills/* ~/.agents/skills/
```

skrepka поставляет только навыки (без хуков, MCP-серверов и субагентов), поэтому отдельный манифест плагина для Codex не требуется, достаточно `SKILL.md` в стандартном каталоге.

## Что помнит агент, а что делает человек

Первичную авторизацию (`skrepka init`) проходит человек. Правила безопасности в каждом навыке говорят это прямо: `init`, `logout`, `revoke` и `forget` запускает человек, агент не проходит OAuth за вас.

Резолв комментариев тоже за человеком — отдельного навыка для `resolve` нет вовсе. `resolve` и `reply --resolve` без флага `--yes` отказывают, а сам флаг заведён для собственных скриптов человека: правила агента запрещают ему резолвить в любом случае. Разрушительная полная замена требует явного режима всегда: с r19 `update` без режима отказывает и не делает ничего — ни на документе с комментариями, ни на пустом, — а живая замена требует `--replace-existing`, `--base <сайдкар>` и `--acknowledge-loss` одновременно. Навык `skrepka-transfer` сверх этого требует спрашивать человека перед любой полной заменой и ждать явного «да»: флаг — отметка о согласии, а не доказательство. Спрашивать нужно, назвав альтернативу: правки в комментированный документ вносит `patch`, треды при этом выживают, а остаток непримененного — список для человека, а не повод для полной замены.

Подробнее в [`agents/CONTRACT.md`](../agents/CONTRACT.md) §4 и [PRIVACY.md](../PRIVACY.md).

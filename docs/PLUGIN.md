# Плагин и скиллы для ИИ-агента

skrepka поставляет набор **скиллов** — сценарных инструкций, которые агент
подхватывает сам, когда вы просите поработать с документом. Это обычный CLI под
капотом; скиллы лишь учат агента вызывать его безопасно и в правильном порядке.

Формат скиллов — открытый стандарт [agentskills.io](https://agentskills.io)
(`SKILL.md`), который одинаково читают **Claude Code** и **OpenAI Codex**. Дерево
скиллов одно на оба рантайма — лежит в каталоге [`skills/`](../skills).

## Сценарии (скиллы)

| Скилл | Когда срабатывает |
|---|---|
| `skrepka-comments` | «отработай комментарии»: прочитать треды → ответить → поправить текст (`comments` → `reply` → `patch`) |
| `skrepka-transfer` | «выгрузи в markdown / залей правки обратно» (`download` ↔ `sync`/`update`) |
| `skrepka-publish` | «опубликуй файл в Drive»: `.md` как гугл-док или любой файл как есть (`upload` / `upload-file`) |
| `skrepka-suggestions` | «разбери предложенные правки»: суммировать tracked changes и рекомендовать (принять — только руками в UI) |
| `skrepka-whatsnew` | «что нового в доке»: текущие открытые комментарии/предложения + локальное сравнение с прошлой выгрузкой (серверной истории у skrepka нет) |

Каждый скилл вшивает короткое **ядро безопасности** (тот же блок, что в
[`agents/CONTRACT.md`](../agents/CONTRACT.md) §5) — Codex подгружает `SKILL.md`
уже после выбора скилла, поэтому внешний контракт сам по себе может не
прочитаться, и ядро дублируется намеренно. CI-тест
(`tests/test_skill_kernel.py`) проверяет, что это ядро байт-в-байт одинаково во
всех скиллах и совпадает с контрактом — против дрейфа.

> **Важно:** `pipx install skrepka` (wheel) ставит только CLI-движок и **не**
> устанавливает скиллы. Сами файлы скиллов есть и в git-репозитории, и в исходном
> архиве (sdist), но подключаются отдельно — через маркетплейс плагинов или ручным
> копированием, как ниже.

## Установка для Claude Code

Репозиторий — это плагин Claude Code: в корне лежат
[`.claude-plugin/plugin.json`](../.claude-plugin/plugin.json) и
[`marketplace.json`](../.claude-plugin/marketplace.json), скиллы подхватываются из
`skills/`.

- **Как плагин (рекомендуется).** Подключите маркетплейс из репозитория и
  установите плагин:

  ```
  /plugin marketplace add slvfmts/skrepka
  /plugin install skrepka@skrepka
  ```

  Скиллы будут доступны с префиксом плагина, например `/skrepka:skrepka-comments`.
- **Вручную (без плагина).** Склонируйте репозиторий и скопируйте нужные
  подкаталоги `skills/*` в `~/.claude/skills/` — тогда они видны как личные скиллы
  (`/skrepka-comments`).

В обоих случаях агент может выбрать скилл и сам — по его `description`, когда вы
формулируете задачу словами («отработай комментарии в этом доке»).

## Установка для OpenAI Codex

Codex читает нативные скиллы того же формата из `~/.agents/skills/` (на уровне
пользователя) или `.agents/skills/` (на уровне репозитория). Склонируйте
репозиторий и скопируйте (или сделайте симлинк) нужные подкаталоги:

```bash
git clone https://github.com/slvfmts/skrepka
mkdir -p ~/.agents/skills
cp -R skrepka/skills/* ~/.agents/skills/
```

skrepka поставляет **только скиллы** (без хуков, MCP-серверов и субагентов),
поэтому отдельный манифест плагина для Codex не требуется — достаточно `SKILL.md`
в стандартном каталоге.

## Что помнит агент, а что делает человек

- **Первичная авторизация (`skrepka init`) — задача человека.** Ядро безопасности
  в каждом скилле прямо говорит: `init`/`logout`/`revoke`/`forget` запускает человек,
  агент не проходит OAuth за вас.
- **Резолв комментариев и деструктивные операции — за человеком.** Отдельного
  скилла для `resolve` нет. Human-gate CLI (интерактивный TTY) держит `resolve` /
  `reply --resolve`, а деструктивную полную замену `update --acknowledge-loss` — при
  наличии комментариев **или** именованных диапазонов (на документе без тех и других
  `update` гейтом не защищён). Скилл `skrepka-transfer` документирует `update` именно
  как то, что подтверждает или делает человек, — агент его не продавливает.
- **Статус.** Agentic-использование 0.9 — **beta / hardened preview**, а не
  верифицированное Google приложение; поведенческая приёмка ядра (`internal/MANUAL-TEST-r4.md`)
  ещё не прогнана. Механические гейты CLI и контракт действуют, но полагаться на них
  как на границу compliance нельзя. Подробнее —
  [`agents/CONTRACT.md`](../agents/CONTRACT.md) §4 и [PRIVACY.md](../PRIVACY.md).
